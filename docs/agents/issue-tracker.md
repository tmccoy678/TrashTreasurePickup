# Issue tracker: GitHub

Project issues and pull requests live in [the surviving repository](https://github.com/tmccoy678/draft2staged-pickup/issues). Use the GitHub CLI with an explicit repository when following historical cross-repository links.

Read an issue and its comments before implementation. Use a UTF-8 body file with `--body-file` for issue, PR, and comment text. Link the originating issue from commits and PR descriptions. Keep an issue open until its changes are integrated and acceptance evidence is recorded.

Triage-ready work uses `ready-for-agent`. Default role labels are `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, and `wontfix`; create labels only when used. **PRs as a request surface: no.**

Publishing preparation, changing repository visibility, and publishing a release are separate actions. Follow the current user's approved scope.
