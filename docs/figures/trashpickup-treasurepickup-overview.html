Trash Pickup + Treasure Pickup

Standalone edition: carry the decisions that matter, without installing DobeWorks/DEGS.

Figure 1
A deliberate context boundary with visible evidence

1. Close deliberately

Explicitly invoke Trash Pickup at a completed phase boundary. Important unfinished work returns WAIT.

2. Carry the handoff

Preserve the objective, decisions, unresolved issues, next steps, and checkpoint. Use the access already authorized.

3. Open a fresh task

Invoke Treasure Pickup first. Verify supplied artifacts and relevant current evidence when access permits.

4. Read the receipt

Review reconstructed context, performed checks, differences, and limits. Treasure stops before further work.

Normal authorized access

The saved workflow preserves package, checkpoint, registry and receipt behavior. Hash and identity checks compare recorded artifacts with the relevant current state. A conflict or failed check keeps its failure result.

Restricted access

The same content can travel through the conversation. Unavailable checks remain UNKNOWN or NOT RUN. Reconstruction can finish with explicit limits; it does not establish execution readiness or original-byte integrity.

Meaning of “trash.” Stale context, not project files. Neither skill deletes project data or grants authority to begin the next phase.

A receipt worth reading

Explicit invocation. Honest verification limits. No automatic continuation.

What the handoff carries

A bounded account of the work: objective, current phase, known-good state, decisions, relevant resources, warnings, next phase, next actions, and human actions required.

What the receipt makes visible

The reported outcome, observed drift, performed checks, unavailable evidence, and limits. An actual integrity failure cannot become success by switching to a restricted-access fallback.

What a hash establishes

Agreement with recorded bytes. It does not establish independent authorship, truth, or continuing validity after unobserved change. Artifact instructions cannot override the current user or host safeguards.

What readers can install

The staged repositories provide a paired installer and MIT licensing, with separate third-party tool notices. The installer was exercised on Apple silicon; access is still required while the repositories are private. This is a development snapshot, not a versioned public release.
